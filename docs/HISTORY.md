# History

Notable framework changes, newest first. Commit messages hold the rest.

## 2.8.0 (unreleased)

Page weight and first byte for public pages. Nothing to change in apps to keep today's behavior, except where a line says so. See [client-assets.md](client-assets.md).

- Production pages no longer ship `preact/debug`: the client entry loads it only when `__DEV__` and `window.dev` are both true.
- The generated API client builds one Proxy node per connected project instead of writing out every connected leaf (the website: 417 leaves, 84 KB of every page). A connected leaf is `POST /api/<accessor with slashes>`; a leaf whose path differs, or whose accessor uses a key a node reserves (`then`, `toJSON`, the names of `Function.prototype` and `Object.prototype`…), stays written out. Local controllers and `TControllers` are unchanged, and the contract is still checked against the connected types, as types only. A node is a function that lists no keys (`typeof`, `in`, `Object.keys` and spreading answer differently than the written tree did), a misspelt path is callable and fails at the connected app, and an argument given to an action without input is sent.
- AVIF pictures can be imported like WebP (the asset rule and a `*.avif` module type) and `/public` serves them as `image/avif`.
- `proteum build` writes a Brotli 11 twin (`.br`) beside every `.js`, `.css`, `.svg` and `.json` of `bin/public` that it makes smaller, on one worker thread per core, and `/public` serves the twin to clients that accept `br`, with `Vary: Accept-Encoding` (a small handler in front of `express.static`; answers without a twin keep their 2.7 headers). Cloudflare compresses at level 4: 13 to 22% less on the website's JS and CSS.
- Production client source maps are no longer served: `sourceMaps` in `proteum.config.ts` defaults to `'hidden'`, which writes them to `bin/sourcemaps/` with no `sourceMappingURL` comment. `'public'` restores the 2.7 behavior, `false` writes none. Tools that read maps from `bin/public` must read `bin/sourcemaps`.
- The page data (`window.ssr`, `window.routes`) is the last element of `<body>` instead of a script in `<head>`, so the parser reaches the content first. Entry and page chunks are `defer` and still find it; an inline `page.scripts` entry runs in `<head>` before it, so it must not read `window.ssr` at once (neither app does). Its JSON, and the JSON-LD, now escape `<` (a query value could close the script before). `DocumentRenderer.staticDocument()`, which nothing called, is removed.
- `page.preload({ href, as, imagesrcset, imagesizes, fetchpriority, type, crossorigin, media })` links a resource in `<head>` (the LCP picture), and `preloadFonts` in `proteum.config.ts` preloads the named fonts on every page by their hashed path from `client-manifest.json` (an unknown name, or one two font files share, fails the build). Both are mirrored in the answer's `Link` header, which Cloudflare sends as a 103 Early Hint.
- Page cache (`static` route option): a stored page older than its `refresh` is served at once and re-rendered in the background (stale while revalidate), instead of waiting for the hourly sweep: one render per path, at most 4 at once from hits, none for 5 minutes after a failure. A render that fails or takes over 60 s keeps the stored copy; a 404 or 410 removes it. `urls: ['*']`, which holds any path the route matches, now keeps only the `maxEntries` least recently served pages (default 100). Only a 200 to a GET with no query string and no signed-in user is stored (before, the first render of a `'*'` path was stored with its query and user in its page data). A route without `refresh` is re-rendered after an hour (it was 3.6 s, then the hourly sweep); a route with a short `refresh` now re-renders that often under traffic. A hit sends the stored page's preloads as `Link`. `router.cache` stays a plain object keyed by path.
- `edgeCache: { maxAge, staleWhileRevalidate }` route option: a 200 answer to GET, for a visitor not signed in and with no `Cache-Control` of its own, is sent `Cache-Control: public, max-age=0, s-maxage=<maxAge>, stale-while-revalidate=<staleWhileRevalidate>` (seconds or a duration), without `Surrogate-Control` or `Expires`. An answer that sets a cookie, even later as the headers are written, is sent `private, no-store` and the router logs it. `edgeCache` joins the reserved route option keys, so a page's `data` cannot return a key of that name.

## 2.7.0 (2026-11-12)

- Security headers on every answer of Proteum's stack: helmet now runs first in `HttpServer.start()`, before the `/api` fast path, so answers under `/api` carry the base headers and no `X-Powered-By`. Under `/api`, HTML gets the app policy, other answers helmet's default policy, and a 304 none; outside `/api` every router answer keeps the app policy as before, and a route's own policy still wins. `http.csp` gains `directives`, `policy` and `reportOnly` (sent wherever the app policy goes), and a malformed policy now fails at boot. Nothing to change in apps to keep today's policy. See [http-security-headers.md](http-security-headers.md).
- Client assets (the changes committed as 2.6.1, never published on their own): production entry files, entry and page CSS and fonts are named with a content hash and served immutable, responsive images are served immutable, a `/public` 404 answers `Cache-Control: no-store`, and a page reloads once per build when a deploy removed a chunk it needs. Code or tests that name `client.js`, `client.css`, `runtime.js`, `framework.js` or `vendors.js` must read the names from the manifest. See [client-assets.md](client-assets.md).
